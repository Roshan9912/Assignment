# Local Linux Hardware Assistant

A dependency-free CLI that answers basic CPU, memory, storage, and GPU questions using read-only Linux system data. By default, a deterministic router selects an inspection tool and reports only parsed facts. An optional local Ollama model can select a tool through Ollama's function-calling API; its selection is validated against the question and fixed allow-list before any system command runs. Unavailable details remain explicitly unknown.

## Requirements

- Python 3.10+
- Linux
- Optional system utilities: `lscpu`, `lsblk`, `lspci`, and `dmidecode`

Missing utilities or inaccessible data are reported instead of guessed. Memory totals can fall back to `/proc/meminfo`; slot counts and maximum capacity require readable `dmidecode` output. This program never runs `sudo` or requests elevated privileges.

## Run

```bash
python3 hardware_assistant.py
python3 hardware_assistant.py --ask "How much RAM do I have?"
python3 hardware_assistant.py --ask "Is my SSD NVMe?" --json
python3 hardware_assistant.py --ask "What GPU do I have?" --ollama-model qwen2.5:7b
```

Interactive follow-ups such as “and what about the GPU?” are supported. Type `quit` or `exit` to leave. `--json` prints normalized facts for the selected topic, which is useful for debugging and demos.

For the optional LLM mode, install and start Ollama locally, then pull a model (for example, `ollama pull qwen2.5:7b`). The client connects only to `127.0.0.1:11434`; it has no cloud fallback. The model selects a no-argument tool, while final user-facing prose is generated from validated facts by deterministic templates rather than generated by the model.

## Safety and design

- LLM/user text is never interpreted as a shell command or passed as system-command arguments. Tool calls have no accepted arguments and must match the deterministic question topic.
- The only subprocess calls come from a fixed command registry, use argument arrays with `shell=False`, a five-second timeout, and no privilege escalation.
- `lsblk` JSON is parsed as data; other command output is normalized into small structured records before answering.
- Default mode is offline. Optional Ollama mode sends the question only to the local Ollama service; there is no cloud fallback or telemetry.
- Responses avoid making claims unsupported by collected facts. In particular, installed RAM and board maximum do not establish which memory module is compatible; consult the laptop manufacturer's specification before upgrading.

## Production-ready notes

This project is organized as a small Python CLI package ready for git, packaging, and GitHub hosting. It keeps the shipped runtime intentionally narrow:

- no arbitrary shell execution
- no cloud calls in default mode
- no privilege escalation
- explicit unknowns instead of guesses
- deterministic tool routing and answer templates

## Tests

Run the standard-library test suite:

```bash
python3 -m unittest discover -s tests -v
```

Tests use mocked command results and do not require Linux utilities or hardware access.

## Current scope

The intent router supports CPU, memory/RAM, storage/SSD, and GPU questions. Ollama function calling is optional so the assistant remains usable without a model server. The model is used only to select an allow-listed tool; deterministic answer templates keep generated claims out of the trusted response path.
